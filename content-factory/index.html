บทที่ 01 · Phase 0 — เปิดโรงงาน

จากพนักงานเดี่ยว สู่ทีมบอทในเพจเดียวกัน

~15 นาที — จบแล้วคุณจะชี้ผังโรงงานคอนเทนต์ได้ทุกชิ้น และตอบได้ว่า "หลายบอท" ในคอร์สนี้แปลว่าอะไรกันแน่ (คำตอบอาจไม่ใช่แบบที่คิด)

ก่อนเริ่ม — คอร์สนี้ต่อยอดจากคอร์ส 1

คุณต้องมีของครบจาก คอร์ส 1 แล้ว: VPS ที่ SSH เข้าได้ · Hermes รันใน Docker · ต่อ Telegram แล้ว · เพจ Facebook พร้อม Page token ถาวร · ระบบโพสต์รูปวันละ 2 เวลาเดินอยู่ ถ้ายังไม่ครบ กลับไปเก็บคอร์ส 1 ให้จบก่อน — ทุกบทในนี้ยืนบนของพวกนั้นทั้งหมด

เพจเดิม แต่เมนูคอนเทนต์ใหญ่ขึ้น 3 เท่า

คอร์ส 1 จบด้วยเพจ "บทเรียนชีวิต" ที่โพสต์ภาพคำคมเองวันละ 2 โพสต์ คอร์สนี้เราจะทำให้เพจเดียวกันนั้นเสิร์ฟได้ 3 เมนู:

เมนูคืออะไรสร้างในบท
🎨 ภาพเดี่ยว (อัปเกรด)ภาพคำคมแบบเดิม แต่หลายเทมเพลต หลายสไตล์ ไม่จำเจ04
🖼 ภาพชุด (carousel) + อัลบั้มโพสต์เดียวหลายภาพ เลื่อนดูได้ + จัดเก็บเข้าอัลบั้มเป็นระบบ05
🎬 วิดีโอ / Reelsคำคมกลายเป็นคลิปสั้น ภาพซูมช้าๆ + ตัวหนังสือ + เพลง06–08

"หลายบอท" ที่แปลว่า "หลายบทบาท"

ข่าวที่อาจเซอร์ไพรส์: เราจะไม่ติดตั้ง Hermes เพิ่มสักตัว — Hermes ตัวเดิมของคุณนั่นแหละจะกลายเป็นทีมทั้งทีม

กลับไปดูสิ่งที่คุณสร้างในคอร์ส 1: งาน morning-quotes, งาน post-morning, งาน post-evening — สังเกตไหมว่าจริงๆ แล้วมันคือ "พนักงานคนละคน" อยู่แล้ว? แต่ละงานตื่นมาทำหน้าที่ของตัวเอง เสร็จแล้วหายไป ไม่รู้จักกันด้วยซ้ำ สิ่งเดียวที่เชื่อมพวกมันคือคิวกลาง (queue.jsonl)

นิยามที่ใช้ทั้งคอร์ส

บอท 1 ตัว = บทบาท 1 บทบาท = งานประจำ (cron) 1 งาน + ทักษะ (skill) 1 ชุด ที่ทำหน้าที่เดียวให้เก่ง แล้วส่งไม้ต่อผ่านคิวกลาง — ไม่ใช่โปรแกรมแยกตัวใหม่ เหมือนพนักงานร้านอาหารคนเดียวที่สลับหมวก: หมวกเชฟ หมวกแคชเชียร์ หมวกเด็กเสิร์ฟ ใส่ทีละใบตามเวลา แต่มองจากลูกค้าเหมือนมีทีมทั้งร้าน

วิธีนี้ได้ทีมโดยไม่จ่ายเพิ่มสักบาท ไม่กิน RAM เพิ่ม และของทุกชิ้นจากคอร์ส 1 ใช้ต่อได้หมด (แบบแยกโปรแกรมจริงก็มีเหตุให้ทำ — บท 03 จะบอกว่าเมื่อไหร่)

ผังโรงงาน — ภาพนี้คือทั้งคอร์ส

เทียบกับผังคอร์ส 1: กล่องส้ม (VPS/Docker/Hermes) และกล่องเขียว (คุณ) อยู่ครบที่เดิม สิ่งที่งอกคือบทบาทในทีม (นักวางแผน/ช่างภาพ/ช่างวิดีโอ), คิวกลางฉลาดขึ้น (รู้จักชนิดงาน), และปลายทางหลากขึ้น (ภาพ/ภาพชุด/วิดีโอ ลงเพจเดิม)

บทที่ 02 · Phase 1 — ทีมบอท

คิวกลาง v2 — สมุดงานกลางที่ทีมทั้งทีมยึดถือ

~20 นาที — จบแล้วคิวของคุณจะรองรับงานภาพและวิดีโอในไฟล์เดียว และคุณจะรู้กติกาทองที่กันทีมบอท "เหยียบเท้ากัน"

ทำไมต้องอัปเกรดคิว

คิวจากคอร์ส 1 มีสมมติฐานซ่อนอยู่ข้อหนึ่ง: ทุกงานคือภาพคำคม พอโรงงานมี 3 เมนู สมมติฐานนี้พัง — นักโพสต์ตอน 19:00 ต้องรู้ว่าคิววันนี้เป็นภาพหรือวิดีโอ ช่างวิดีโอต้องรู้ว่างานไหนของตัวเอง วิธีแก้คือเพิ่ม field ให้แต่ละบรรทัดในคิว "ประกาศชนิดตัวเอง"

โครงบรรทัดคิว v2

{"text": "ล้มแล้วลุกช้าหน่อยก็ได้ ขอแค่ลุก",
 "author": "",
 "type": "video",
 "status": "ready",
 "added": "2026-08-27",
 "slot": "2026-08-29 19:00",

fieldความหมายใหม่ใน v2?
text / authorคำคม + เจ้าของคำ (ว่าง = ออริจินัล)เดิม

ความเข้ากันได้กับของเดิม (สำคัญ)

กติกา: บรรทัดที่ไม่มี type ให้ทุกบอทถือว่าเป็น image — งานเก่าในคิวของคุณจึงไม่ต้องไล่แก้สักบรรทัด ระบบเดิมเดินต่อได้ระหว่างที่เราค่อยๆ ต่อเติม นี่คือวิธีอัปเกรดระบบที่กำลังรันจริง: เพิ่มของใหม่แบบที่ของเก่าไม่รู้สึกตัว

สถานะคือไม้ผลัด (baton) — ภาพวงจรชีวิตงานวิดีโอ

ทำไมวิดีโอต้องมีขั้น rendering/rendered คั่นกลาง? เพราะเรนเดอร์วิดีโอกินเวลาหลายนาที ถ้าให้นักโพสต์ 19:00 ทำเองสดๆ โพสต์จะเลท และถ้าเรนเดอร์พังเราจะรู้ตัวตอน 19:00 พอดี — สายเกินแก้ การให้ช่างวิดีโอทำล่วงหน้าตอน 17:00 คือการซื้อเวลา 2 ชั่วโมงไว้กู้สถานการณ์ (หลักคิดเดียวกับ "ซ้อมด้วย cron run ก่อนของจริง" ในคอร์ส 1)

กติกาทอง: หนึ่ง field หนึ่งเจ้าของ (single-writer)

ปัญหาคลาสสิกของระบบหลายคนทำงานไฟล์เดียว: สองบอทเขียนพร้อมกันแล้วข้อมูลทับกัน (ศัพท์เรียก race condition) วิธีกันที่ง่ายและได้ผลสุดสำหรับโรงงานขนาดเรา: กำหนดเจ้าของการเขียนให้ชัด — สถานะแต่ละช่วงมีบอทเดียวที่มีสิทธิ์เปลี่ยน

การเปลี่ยนสถานะเจ้าของสิทธิ์ (คนเดียวเท่านั้น)
เพิ่มบรรทัดใหม่ ready🧠 นักวางแผน (หลังคุณพิมพ์ "อนุมัติแผน")
ready → rendering → rendered + เติม asset🎬 ช่างวิดีโอ
ready/rendered → posted📮 นักโพสต์
อะไรก็ได้ → cancelled📱 คุณ (สั่งผ่านแชท) เท่านั้น

กติกานี้จะถูกฝังลงใน skill ของทุกบทบาทที่เราสร้างในบทถัดๆ ไป — บอทที่ไม่ใช่เจ้าของ ห้ามแก้ ต่อให้เห็นว่า "น่าจะผิด" ก็ให้รายงานคุณแทนการแก้เอง

บทที่ 03 · Phase 1 — ทีมบอท

ตั้งทีมบอท — บทบาท ชื่อเรียก และเส้นแบ่งหน้าที่

~25 นาที — จบแล้วคุณจะมีผังทีมที่เขียนเป็นลายลักษณ์อักษร รู้ต้นทุนจริงของ "บอทแยกตัวจริง" และเช็กสุขภาพเครื่องก่อนเปิดไลน์ผลิตใหม่เป็น

🎯 ภารกิจบทที่ 03 — เช็กเครื่องก่อนเปิดไลน์ผลิต

SSH เข้า VPS แล้วรัน 3 คำสั่ง (ทีละคำสั่ง ดูผลก่อนไปต่อ):

free -h        # RAM เหลือพอไหม (ffmpeg ตอนเรนเดอร์กินชั่วคราว ~200-500MB)
df -h /        # ดิสก์เหลือกี่ GB (ไฟล์วิดีโอใหญ่กว่าภาพ ~10 เท่า)
docker exec -it hermes-agent-xxxx-hermes-agent-1 hermes cron list   # ทีมปัจจุบันมีใครบ้าง

ส่งผลทั้ง 3 มาให้ครูดู — โดยเฉพาะตัวเลข RAM ว่าง กับดิสก์ว่าง เราจะใช้ตัดสินคุณภาพวิดีโอ (ความยาว/ความละเอียด) ในบท 07

บทที่ 04 · Phase 2 — ไลน์ผลิตภาพ

โรงงานภาพหลายเทมเพลต — เพจเดิมแต่ไม่จำเจ

~30 นาที — จบแล้ว make_image.py ของคุณจะทำภาพได้ 3 สไตล์ และคุณจะได้เทคนิคสำคัญ: วิธี "จ้าง Hermes อัปเกรดโค้ดของมันเอง" อย่างปลอดภัย

ปัญหาที่คนตามเพจจะรู้สึกก่อนคุณ

เทมเพลตเดียวทุกวัน ผ่านไปเดือนหนึ่ง feed ของเพจจะดูเหมือน "ภาพเดิมเปลี่ยนตัวหนังสือ" ความจำเจฆ่าเพจช้าๆ วิธีแก้ไม่ใช่สุ่มมั่ว แต่คือผูกสไตล์ภาพกับธีมของวัน ที่เราออกแบบไว้ตั้งแต่คอร์ส 1 (จันทร์-ความพยายาม, กลางสัปดาห์-ใจเย็นกับตัวเอง, ศุกร์-ปล่อยวาง ฯลฯ)

สไตล์หน้าตาเหมาะกับธีม
classicพื้นครีม ตัวหนังสือเข้ม (ตัวเดิมจากคอร์ส 1)ความพยายาม / การเริ่มใหม่
nightพื้นเข้มเกือบดำ ตัวหนังสือสว่าง โทนสงบการปล่อยวาง / โพสต์เย็น 19:00
paperโทนกระดาษโน้ต เส้นบรรทัดจางๆ อบอุ่นใจเย็นกับตัวเอง / คำสอนคนดัง

เทคนิคหลักของบทนี้: จ้าง Hermes แก้โค้ดตัวเอง — แบบมีเข็มขัดนิรภัย

คุณไม่ต้องเขียน Python เอง — Hermes แก้ให้ได้ แต่การปล่อยให้ AI แก้สคริปต์ที่ระบบจริงใช้อยู่ มีกติกาความปลอดภัย 3 ข้อที่ต้องอยู่ใน prompt เสมอ:

  1. สำรองก่อนแตะ — ให้มัน cp ไฟล์เดิมเก็บไว้ก่อนเสมอ พังเมื่อไหร่ย้อนได้ใน 1 คำสั่ง
  2. ของเดิมต้องเดินต่อได้ — เรียกแบบไม่ระบุสไตล์ ต้องได้ผลแบบเดิมเป๊ะ (default = classic) เพราะงานโพสต์เช้า/เย็นตัวจริงกำลังเรียกใช้อยู่ทุกวัน
  3. พิสูจน์ด้วยตา ไม่ใช่คำพูด — จบงานต้องส่งภาพตัวอย่างครบทุกสไตล์เข้า Telegram ให้คุณดูจริง ไม่รับคำว่า "เสร็จแล้วครับ" เปล่าๆ
กฎจากสนามจริง (คอร์ส 1 สอนเราแล้ว)

AI ชอบ "over-engineer" — ขยันเกินสั่งจนพัง (เคสจริง: สร้าง path สคริปต์ซ้อนกันเอง) prompt ที่ดีจึงต้องมีทั้ง "สิ่งที่ให้ทำ" และ "สิ่งที่ห้ามทำ" เขียนชัดๆ ทุกครั้ง

Prompt อัปเกรดช่างภาพ (แม่แบบใช้จริง)

อัปเกรดสคริปต์ทำภาพคำคม (make_image.py) ตามนี้:
1. ก่อนแก้ ให้สำรองไฟล์เดิมเป็น make_image.py.bak ก่อน
2. เพิ่ม argument --style รับค่า classic | night | paper
   - classic: แบบเดิมทุกอย่าง และต้องเป็นค่า default เมื่อไม่ระบุ
   - night: พื้นหลังโทนเข้ม (#1a1a2e) ตัวหนังสือสีครีม
   - paper: พื้นหลังโทนกระดาษ (#f5efe0) เส้นบรรทัดจางๆ ตัวหนังสือน้ำตาลเข้ม
3. ห้ามแก้ส่วนอื่นของสคริปต์ ห้ามเปลี่ยนขนาดภาพ ห้ามเปลี่ยนฟอนต์
4. เสร็จแล้วทดสอบ: ทำภาพคำคมเดียวกันทั้ง 3 สไตล์
   แล้วส่งทั้ง 3 ภาพเข้า Telegram ให้ผมดู

เชื่อมกับแผนสัปดาห์

ต่อจากนี้ นักวางแผนจะใส่สไตล์ลงคิวได้ด้วย field เสริม "style": "night" — นักโพสต์อ่านแล้วส่งต่อให้ช่างภาพ ถ้าบรรทัดไหนไม่มี style นักโพสต์ใช้กติกาง่ายๆ: โพสต์เช้า = classic/paper สลับกัน, โพสต์เย็น = night (กติกานี้จะเขียนลง skill นักโพสต์ในบท 09)

บทที่ 05 · Phase 2 — ไลน์ผลิตภาพ

ภาพชุด (carousel) + อัลบั้ม — โพสต์เดียวเล่าได้หลายจังหวะ

~30 นาที — จบแล้วเพจคุณจะโพสต์ "ชุดคำคม 3 ภาพเลื่อนดู" ได้ และคำถามค้างจากคอร์ส 1 ("เก็บรูปเข้าอัลบั้มได้ไหม") จะได้คำตอบเป็นโพสต์จริง

carousel ทำงานยังไงใน Graph API — เทคนิค 2 จังหวะ

Facebook ไม่มีปุ่ม "โพสต์หลายภาพ" ตรงๆ ใน API แต่ใช้ท่ามาตรฐาน 2 จังหวะ:

  1. อัปโหลดภาพแบบ "ยังไม่เผยแพร่" — ยิง /photos ทีละภาพพร้อม published=false ภาพจะขึ้นไปรอบนเซิร์ฟเวอร์เงียบๆ ไม่โผล่บนเพจ แต่เราได้ id ของแต่ละภาพกลับมา
  2. ประกอบร่างเป็นโพสต์เดียว — ยิง /feed หนึ่งครั้ง แนบรายการ id ทั้งหมดผ่าน attached_media → กลายเป็นโพสต์ carousel โพสต์เดียว
# จังหวะ 1 — อัปโหลดเงียบ ทีละภาพ (ทำซ้ำ 3 ครั้ง เก็บ id ทุกใบ)
curl -X POST "https://graph.facebook.com/v26.0/PAGE_ID/photos" \
  -F "access_token=PAGE_TOKEN" \
  -F "published=false" \
  -F "source=@/opt/data/home/.hermes/page/out/q1.png"
# ตอบกลับ: {"id":"111111"}  ← จดไว้

# จังหวะ 2 — ประกอบเป็นโพสต์เดียว
curl -X POST "https://graph.facebook.com/v26.0/PAGE_ID/feed" \
  -F "access_token=PAGE_TOKEN" \
  -F "message=3 บทเรียนสั้นๆ ก่อนเริ่มสัปดาห์ 🌱" \
  -F 'attached_media[0]={"media_fbid":"111111"}' \
  -F 'attached_media[1]={"media_fbid":"222222"}' \
  -F 'attached_media[2]={"media_fbid":"333333"}'
จุดพลาดยอดฮิต

ค่าใน attached_media[n] ต้องเป็นก้อน JSON ในเครื่องหมายคำพูด (สังเกต single quote ครอบทั้งก้อน) — ถ้าใส่ id เปล่าๆ จะได้ error 100 · และต้องใช้ Page token ตัว Never expire จากคอร์ส 1 เหมือนเดิมทุกจังหวะ

อัลบั้ม — คำตอบของคำถามค้างจากคอร์ส 1

อัลบั้มคือ "โฟลเดอร์ภาพบนเพจ" สร้างครั้งเดียวได้ id ถาวร แล้วโพสต์ภาพเข้าอัลบั้มนั้นตรงๆ ได้เลย:

# สร้างอัลบั้ม (ทำครั้งเดียว) — ได้ ALBUM_ID เก็บไว้ใช้ตลอด
curl -X POST "https://graph.facebook.com/v26.0/PAGE_ID/albums" \
  -F "access_token=PAGE_TOKEN" \
  -F "name=คำคมประจำสัปดาห์" \
  -F "message=รวมคำคมรายสัปดาห์ของเพจ"

# โพสต์ภาพเข้าอัลบั้มนั้นโดยตรง (ใช้ ALBUM_ID แทน PAGE_ID)
curl -X POST "https://graph.facebook.com/v26.0/ALBUM_ID/photos" \
  -F "access_token=PAGE_TOKEN" \
  -F "message=คำคมวันจันทร์" \
  -F "source=@/opt/data/home/.hermes/page/out/q1.png"

ไอเดียใช้จริงกับเพจเรา: ให้นักโพสต์เก็บภาพ "ตัวท็อปประจำสัปดาห์" (โพสต์ที่คนไลก์สุด) เข้าอัลบั้มรวมทุกวันอาทิตย์ — คนมาใหม่เปิดอัลบั้มเดียวเจอของดีย้อนหลังครบ

🎯 ภารกิจบทที่ 05 — carousel แรกของเพจ

สั่ง Hermes ใน Telegram (สังเกตว่าเราปักหมุดวิธีที่พิสูจน์แล้ว + บอกสิ่งที่ห้ามทำ — สูตรจากสนามจริง):

ทำโพสต์ carousel ชุดแรกของเพจ ตามขั้นตอนนี้เท่านั้น:
1. เลือกคำคมธีมเดียวกัน 3 ข้อจากคิว (status ready, type image)
2. ทำภาพ 3 ใบด้วยสไตล์ paper ทั้งชุด
3. ส่ง 3 ภาพให้ผมดูใน Telegram ก่อน — รอผมตอบ "โพสต์ได้"
4. โพสต์ด้วยท่า 2 จังหวะ: /photos published=false ทีละใบ
   แล้ว /feed พร้อม attached_media ด้วย curl แบบใน skill post-facebook (v26.0)
5. ห้ามสร้างสคริปต์ใหม่ ห้ามใช้วิธีอื่นนอกจากที่ระบุ
เสร็จแล้วส่งลิงก์โพสต์มายืนยัน อย่าลืมอัปเดต status เป็น posted ทั้ง 3 บรรทัด

ได้ลิงก์โพสต์ carousel แล้วส่งมาให้ครูดู — เปิด incognito เช็กด้วยว่าคนนอกเห็นครบ 3 ภาพ

📚 Glossary — ศัพท์คอร์ส 2

ศัพท์ใหม่ของโรงงานคอนเทนต์ (ศัพท์พื้นฐาน VPS/Docker/Hermes อยู่ใน Glossary ของคอร์ส 1)

ทีมบอท & คิว

ศัพท์ความหมาย
บทบาท (role)"บอท" หนึ่งตัวในคอร์สนี้ = งานประจำ (cron) 1 งาน + skill 1 ชุด ทำหน้าที่เดียว เช่น ช่างวิดีโอ
คิวกลาง v2queue.jsonl ที่เพิ่ม field type (image/video) และ asset (path ไฟล์ผลงาน)
baton (ไม้ผลัด)การใช้ field status ส่งงานต่อระหว่างบอท: ready → rendering → rendered → posted
race conditionอาการสองโปรแกรมเขียนข้อมูลเดียวกันพร้อมกันจนข้อมูลพัง/หาย — ศัตรูเบอร์หนึ่งของระบบหลายบอท
single-writerกติกากัน race condition: สถานะแต่ละช่วงมี "เจ้าของสิทธิ์เขียน" เพียงบอทเดียว
render (เรนเดอร์)การประมวลผลสร้างไฟล์ผลงานจริง (ภาพ/วิดีโอ) — วิดีโอใช้เวลานาน จึงต้องทำล่วงหน้า
assetไฟล์ผลงานที่เรนเดอร์เสร็จ พร้อมใช้โพสต์ เก็บ path ไว้ในคิว

ภาพ & Facebook API

ศัพท์ความหมาย
carouselโพสต์เดียวที่มีหลายภาพเลื่อนดูได้ — สร้างด้วยท่า 2 จังหวะ (อัปโหลดเงียบ → ประกอบ)
published=falseพารามิเตอร์อัปโหลดภาพขึ้นเซิร์ฟเวอร์ FB โดยยังไม่โผล่บนเพจ เพื่อเอา id ไปใช้ต่อ

albumโฟลเดอร์ภาพบนเพจ สร้างได้ทาง API (/albums) แล้วโพสต์ภาพเข้าอัลบั้มด้วย ALBUM_ID/photos
เทมเพลต/สไตล์ชุดหน้าตาภาพ (classic / night / paper) เลือกตามธีมวัน ผ่าน --style ของ make_image.py

วิดีโอ

ศัพท์ความหมาย
ffmpegเครื่องมือฟรีจัดการวิดีโอ/เสียงผ่านบรรทัดคำสั่ง — มีดสวิสของงานวิดีโอทั้งโลก
codec / H.264วิธีบีบอัดวิดีโอ — H.264 (libx264) คือมาตรฐานที่ Facebook และแทบทุกที่รองรับ
yuv420pรูปแบบสีของวิดีโอที่เข้ากันได้กว้างสุด — ลืมใส่แล้ววิดีโอมักเปิดไม่ได้ในบางแอป
fpsเฟรมต่อวินาที — คลิปคำคมใช้ 25 พอ (ตากรรมการดูไม่ออกจาก 30)
aspect ratioสัดส่วนภาพ: 1:1 (จัตุรัส, feed) · 4:5 (feed มือถือ) · 9:16 (แนวตั้งเต็มจอ, Reels)
zoompan / Ken Burnsเทคนิคทำภาพนิ่งให้ "มีชีวิต" ด้วยการซูม/แพนช้าๆ — หัวใจของคลิปคำคมเรา
-shortestตัวเลือก ffmpeg ให้คลิปจบตามสายที่สั้นสุด (เช่น ภาพ 8 วิ + เพลง 3 นาที → คลิป 8 วิ)
Reelsวิดีโอสั้นแนวตั้ง 9:16 ของ FB/IG — โพสต์ผ่าน API ต้องใช้ท่า 3 จังหวะ (start → upload → finish)

⌨️ ffmpeg + คำสั่งโรงงาน — cheat sheet

คำสั่งที่ใช้บ่อยในคอร์สนี้ ก๊อปไปแก้ path/ชื่อไฟล์ได้เลย (คำสั่ง Linux พื้นฐานอยู่ใน cheat sheet คอร์ส 1)

ffmpeg — สูตรสำเร็จของโรงงาน

# 1) ภาพนิ่ง → คลิป 8 วินาที (แบบเรียบสุด ไม่มีลูกเล่น)
ffmpeg -y -loop 1 -i quote.png -t 8 \
  -c:v libx264 -pix_fmt yuv420p -r 25 out.mp4

# 2) + ซูมช้า (Ken Burns) + จอ 1:1
ffmpeg -y -loop 1 -i quote.png -t 8 \
  -vf "scale=1080:1080,zoompan=z='min(zoom+0.001,1.15)':d=200:x='iw/2-(iw/zoom/2)':y='ih/2-(ih/zoom/2)':s=1080x1080:fps=25" \
  -c:v libx264 -pix_fmt yuv420p out.mp4

# 3) + เพลงพื้นหลัง (คลิปจบตามภาพเพราะ -shortest)
ffmpeg -y -loop 1 -i quote.png -i music.mp3 -t 8 \
  -vf "scale=1080:1080,fade=t=in:st=0:d=0.8,fade=t=out:st=7:d=1" \
  -c:v libx264 -pix_fmt yuv420p -c:a aac -shortest out.mp4

# 4) แปลงเป็นแนวตั้ง 9:16 สำหรับ Reels (ขยายเบลอเป็นพื้นหลัง)
ffmpeg -y -i out.mp4 \
  -vf "split[a][b];[a]scale=1080:1920,boxblur=20[bg];[b]scale=1080:-2[fg];[bg][fg]overlay=(W-w)/2:(H-h)/2" \
  -c:v libx264 -pix_fmt yuv420p -c:a copy reel.mp4

# ดูข้อมูลไฟล์วิดีโอ (ยาวกี่วิ ขนาดเท่าไหร่ codec อะไร)
ffprobe -hide_banner out.mp4
